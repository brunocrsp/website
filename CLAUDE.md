# Meshvise Vitrine: Developer Guide

## Project Overview

Marketing site for Meshvise (the SCADA/IIoT product), served at https://meshvise.com and https://www.meshvise.com. Pure static Astro build, deployed via Cloudflare Workers (wrangler). The same Worker handles the contact form (`POST /api/contact`) and still hosts the trial license signer endpoint (`POST /api/trial`) specified by ADR-0006. See cross-repo references below.

## Sister repo and cross-repo context

Paths below are relative to the workspace root, `~/Meshvise`. The Meshvise product app lives in a sister repo at `code/meshvise/` (GitHub: `brunocrsp/meshvise`), branch `dev` (see its own `CLAUDE.md`). **You do not touch that repo.** You only read from it as needed:

- Spec source of truth for the trial license system: `documentation/docs/adr/0006-trial-license-system.md`. Read-only. Defines the JWT claims schema, key isolation rules, expiration sanction, email nurture cadence. Do not improvise off-spec.
- Project status and open work: `documentation/docs/pilotage.md`. The documentation (ADRs, pilotage, audits, pricing grid, EULA) is its own repo, `documentation/` at the workspace root.
- Known cross-repo defects: the audit registry `docs/audits/registre.md` in the documentation repo. **AUD-006**: the product's first boot (`first_boot.py`) requires `issued_to.email`, a claim that ADR-0006 does not define and that `buildTrialClaims` therefore does not set: a trial license issued today never reaches a running interface. The worker follows the spec; the fix belongs to the product or to an ADR-0006 amendment. Do not add the claim to the worker on your own. The cross-repo interfaces are described in the documentation repo's `docs/01-architecture/interfaces-entre-repos.md`.
- **The site must not promise what the product does not do.** Before writing a claim, check it against the audit registry: an open finding (indicator coverage, writes to the process…) makes the claim false today.

The trial signer's public key lives in the meshvise repo (verifier side). The trial signer's private key is a Worker secret on this repo (`TRIAL_SIGNING_KEY`), generated by the user from the meshvise-side script and posted via `wrangler secret put`. The private key never lands in this repo, even temporarily, including in tests, fixtures, comments.

## Stack

| Layer | Choice |
|-------|--------|
| Build | Astro 6 (static build into `dist/`) |
| Edge runtime | Cloudflare Workers via wrangler 4 (`src/worker.js`) |
| CSS | Tailwind v4 + scoped styles, tokens in `src/styles/global.css` |
| i18n | French (default) + English. Routes `/<lang>/`, slugs in `src/i18n/routes.ts` |
| Tests | vitest (`tests/`), including assertions on the built HTML |

The Worker proxies `env.ASSETS` and serves `POST /api/contact`, `POST /api/trial` (plus `/crl.json`). **No page of the site posts to `/api/trial` since 2026-09-22**: the trial is on quote and requested through the Contact page. The endpoint stays because ADR-0006 specifies it for the product. Stay minimal on the edge.

- **Legal pages**: the publisher's identity (name, address, SIREN, phone, publication director) lives in `src/i18n/editeur.ts`, one source for both languages. An empty field shows "à compléter" on the page and **fails the build in CI**: the site cannot be deployed without its publisher. The privacy policy describes exactly what the site collects (the contact form, and the IP address the host sees); a new form, cookie, analytics tool or third-party script changes that page in the same commit.

- **Top bar**: Accueil, Pourquoi superviser, Produit, Protocoles, Tarifs, and the "Voir la démo" button. The mobile menu shows the same list.
- **Removed on 2026-09-23**, do not bring back without Bruno: FAQ, Guides (and the content collection), À propos, Intégrateurs, Essai (trial page), the `preview-motion` pages. The FAQ survives as a section of the pricing page only (`FAQ_KEYS`, seven buyer questions), and its FAQPage structured data is emitted there only (`<Base faq>`).
- **Every "Prendre contact" leads to the Contact page** with the request pre-selected: `/fr/contact/?sujet=licence`, `exploitation`, `essai`, `demo`, `autre`. The form posts to `/api/contact`, which emails contact@meshvise.com through Resend (worker secret `RESEND_API_KEY`); the request sets the email subject. Without the key the endpoint answers an error and the page offers a pre-filled email instead of a false success.
- **Pricing**: one licence per site, 2 400 € per year, support and every update included, major versions too (decision of 2026-09-23, documentation `2d0b225`). Commissioning on quote. Managed operations "on request", not deliverable yet: promise nothing more.

## Design and writing conventions

- **Page grammar** (home, why, product, pricing, contact): a hero with a two-part title whose end is in the accent color, a short subtitle, then a graphite block (`dark-block`) right under it; then full-width bands with alternating backgrounds (canvas, `bg-surface`, graphite). Pages end on "Par où commencer" (`PricingBrief`) rather than a form.
- **Product captures** go in `ProductShot` (a bare application window, 16:10). Without a capture, it reserves the slot with a visible placeholder: do not ship a placeholder to production without saying so.
- **Copy is short and not technical**: one or two sentences per block, the gain rather than the mechanism. No database, protocol-stack or security-standard names outside the Protocols page. No example figures that can be argued with.
- **Animations** live in `components/motion/*Strip.astro` (homepage feature list) and `WhyGains`/`PricingBrief`. They play once when they enter the screen and rest on their last frame; without JS or under `prefers-reduced-motion` they show the final state. Astro does not scope SVG elements rendered inside a conditional expression: use `:global()` under a scoped parent, or render unconditionally.
- **Light first**; dark only for the graphite blocks.

| `master` | Prod, serves `meshvise.com` and `www.meshvise.com` | YES (`.github/workflows/deploy.yml`, runs after CI green on master) |

`origin/dev` is a stale branch of 2026-09, not an ancestor of `master`: do not branch from it.

**Never push to `master` without explicit user approval in the session.** Master push triggers a Cloudflare Workers deploy to prod after CI completion, and CI runs `npm run build` then `npm test`: a red test blocks the deploy. Default workflow: work on the feature branch, the user decides when `master` moves.

## Hard rules

- **No em-dashes (long horizontal hyphen)** in code, copy, comments, emails, JSON values. Use colons, parentheses, periods. Applies in all languages, all files. The built-HTML lint checks every page.
- **No competitor names in marketing copy**: Niagara, Ignition, EcoStruxure, Tridium, Inductive Automation, Workbench, JACE. Refer to the category ("legacy SCADA platforms", "tag-priced SCADA", etc.).
- **Never write the trial signing private key to disk**, even temporarily, even in tests or fixtures. Read it from `env.TRIAL_SIGNING_KEY` at runtime only. The user's Bitwarden vault is the only canonical store.
- **Never frame shortcuts as laziness.** State the real tradeoff (time-boxing, dependency wait, blast-radius minimization).
- **No phone-home in product traffic.** The `/api/trial` Worker ends with the Resend send. The verifier in the sister repo runs offline. Telemetry, if added later, is opt-in and non-blocking. Do not slip in anonymous pings.

## Workflow

1. Commit after each meaningful step, conventional commits, with the attribution trailer given by the session (the model follows the current session).
2. Stage files explicitly; never `git add -A` at the root of the repo.
3. Cross-repo coordination on the trial system: the user is the relay.
4. After a change, build (`npm run build`) **then** test (`npm test`): the built-HTML tests read `dist/`, so tests run before a build check the previous output.

## Quickstart

```bash
npm install                    # one-shot
npm run dev                    # Astro dev server, http://127.0.0.1:4321 (no Worker logic)
npm run build                  # produces dist/
npm test                       # vitest, reads dist/
npx wrangler dev               # local Worker (build dist/ first)
```

## Lancer la vitrine

Le serveur de développement est **fixé sur 127.0.0.1:4321**, avec `strictPort`
(cf. `astro.config.mjs`). Deux raisons, toutes deux constatées sur le poste le
2026-09-11 :

- sans `host`, Astro n'écoute qu'en IPv6, donc `localhost:4321` répond et
  `127.0.0.1:4321` non ;
- sans `strictPort`, un second lancement s'installe **en silence** sur 4322 et
  le doublon devient invisible.

`npm run dev` est le seul lancement. Un second lancement refuse de démarrer :
un refus veut dire que la vitrine tourne déjà sur 4321.

> ⚠ **Le serveur de dev sert parfois l'ancien CSS d'un composant** après une
> modification (le HTML suit, pas le style scopé). `touch` le fichier du
> composant, attendre deux secondes, recharger. Vérifier le CSS servi plutôt
> que de conclure trop vite qu'une règle ne marche pas.

## Key files

- `src/worker.js` Cloudflare Worker entry (`/api/contact`, `/api/trial`, `/crl.json`, static assets)
- `wrangler.jsonc` Worker config, custom domains, bindings (KV, rate limiting, secrets)
- `src/pages/<lang>/*.astro` thin route files; the pages live in `src/components/pages/`
- `src/layouts/Base.astro` head, icons, structured data
- `src/i18n/{fr,en}.json` copy; `motion.{fr,en}.json` texts drawn inside the animations; `faq-keys.ts` the pricing FAQ
- `src/styles/global.css` tokens, typography, `dark-block`, form fields
- `src/pages/llms.txt.ts` and `llms-full.txt.ts` what AI search engines read, both generated from the page texts at build time: never write them by hand
- `tests/built-html.test.ts` assertions on the built static output; `tests/i18n.test.ts` FR/EN symmetry and typography
- `.github/workflows/ci.yml`, `.github/workflows/deploy.yml` CI + auto-deploy
